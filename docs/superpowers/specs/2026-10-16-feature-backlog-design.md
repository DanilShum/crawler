# Бэклог: функции, которые хотелось бы, но сейчас не можем

**Дата:** 2026-10-16
**Статус:** живой документ — куда складываются отложенные идеи вместо их реализации сейчас
**Родительский документ:** docs/superpowers/specs/2026-10-13-seo-crawler-design.md

## Правила работы с документом

Каждая запись фиксирует: что за функция, зачем, **что мешает сделать её сейчас**
и что понадобится для реализации. Записи не участвуют в декомпозиции и планах,
пока их явно не перенесут в отдельную спеку через обычный цикл
brainstorming → спека → план. Устаревшие записи удаляются.

## 1. Проверка орфографии и грамматики

**Суть.** Поиск текстовых опечаток в контенте страниц (как «проверка орфографии
и грамматики» в Screaming Frog).

**Зачем.** Контент-качество: опечатки на коммерческих страницах снижают доверие
и конверсию.

**Что мешает сейчас.**
- Нет внешнего сервиса проверки: рабочий вариант — интеграция с API проверки
  орфографии (Яндекс.Спеллер и аналоги), а это внешняя зависимость: ключи
  (Vault), лимиты, стоимость за объём, сетевые вызовы на каждую страницу.
- Локальный словарь русского языка с морфологией — тяжёлая зависимость
  (десятки МБ) и наивный spellcheck без лемматизации даёт неприемлемо много
  ложных срабатываний на терминологических сайтах.

**Что понадобится.** Выбрать между (а) интеграцией с внешним API-чекером и
(б) локальным словарём; решить вопрос секрета/лимитов; добавить в конвейер
обработки страниц шаг «текст → проверки правописания» с rate-limit.

## 2. Crawl All Subdomains

**Суть.** Режим обхода всех поддоменов основного домена (например,
`blog.example.com` вместе с `example.com`), в т.ч. с авто-обнаружением
поддоменов из robots.txt/ссылок.

**Зачем.** Крупные сайты часто разнесены по поддоменам; аудит одного хоста
упускает часть страниц.

**Что мешает сейчас.**
- Гейт `isInternal` (`url-utils.ts`) сравнивает только origin — нужно
  сравнение по «регистрируемому домену» (eTLD+1), что требует списка публичных
  суффиксов (PSL): `site.ru` и `com.ru` — разная глубина принадлежности.
- Ограничение `MAX_ACTIVE = 3` краула и модель «один origin на сессию»
  (`engine.ts`): смешение поддоменов в одной сессии ломает предположения о
  `crawlDelay` (он per-host, а гейт сейчас общий на сессию).

**Что понадобится.** Зависимость или вырезка из Public Suffix List; флаг
`includeSubdomains` в `CrawlOptions`; пересмотр гейта задержки на per-host.

## 3. Экспорт XLSX / Google Sheets

**Суть.** Экспорт результатов в XLSX и выгрузка напрямую в Google Sheets
(Screaming Frog умеет CSV, XLS, XLSX, GSHEET).

**Зачем.** Клиенты чаще получают таблицы в Excel/Sheets, чем открывают CSV;
форматирование и листы с issue-отчётами читаемее.

**Что мешает сейчас.**
- Для XLSX нужна библиотека (xlsx/exceljs) — заметная зависимость и
  поверхность атак (история уязвимостей парсеров XLSX); CSV закрывает
  техническую потребность уже сейчас.
- Для Google Sheets нужен OAuth-проект и keychain — отдельная инфраструктура
  (правило проекта: авторизация только через OzonID/Ozon Key, внешние
  интеграции требуют отдельного согласования).

**Что понадобится.** Решение по библиотеке XLSX и её аудиту; для GSHEET —
обсуждение интеграции и хранения токенов (Vault).

## 4. Сравнение сканирований (Compare Crawls)

**Суть.** Сопоставление результатов двух проходов по URL: новые/исчезнувшие
страницы, изменение статусов, title и т.д.

**Зачем.** Проверка эффекта исправлений между аудитами.

**Что мешает сейчас.** Сессии живут в памяти процесса и умирают вместе с ним —
сравнивать просто нечего (это же блокирует подсистему C «персистентность»).

**Что понадобится.** Персистентность результатов (подсистема C), затем отдельная
спека на diff: хранение снапшотов, выбор базового краула, UI-режим сравнения.

## 5. Интеграции Google Analytics / Search Console

**Суть.** Импорт данных трафика и позиций (GA4, GSC) поверх результатов краула;
режим SERP (URL из GSC как список обхода).

**Зачем.** Приоритизация проблем по трафику: битая страница с 10k визитов
важнее битой страницы без трафика.

**Что мешает сейчас.** Внешние OAuth-интеграции и хранение токенов — отдельное
инфраструктурное согласование (как в п. 3); сервис задуман как инструмент без
авторизации.

**Что понадобится.** Согласование OAuth-проекта, Vault для токенов; затем
спека на импорт (сначала read-only импорт CSV из GSC как упрощение без API —
возможный промежуточный шаг).
