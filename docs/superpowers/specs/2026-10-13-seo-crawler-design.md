# Дизайн: веб-приложение-краулер (аналог Screaming Frog SEO Spider)

Дата: 2026-10-13
Статус: утверждено (разделы 1–3 одобрены пользователем)

## 1. Цель

Веб-приложение, которое имитирует поведение поискового бота: пользователь
указывает стартовый URL, приложение обходит сайт и собирает технические
данные (статусы, мета-теги, заголовки, ссылки, директивы индексации),
затем показывает результаты в таблицах и готовых отчётах о проблемах.

### Объём v1

- Режимы обхода: **Spider** (по внутренним ссылкам), **List** (вручную или CSV),
  **Sitemap** (по XML-карте сайта, авто-обнаружение через robots.txt).
- Сбор данных по странице: HTTP-статус и заголовки ответа, title, description,
  meta-robots, h1–h6, изображения с признаком alt, внутренние/внешние ссылки,
  canonical, noindex/nofollow, Schema.org (JSON-LD), размер и время ответа.
- Отчёты о проблемах: битые ссылки, дубли title/description/h1, отсутствие h1,
  изображения без alt, noindex-страницы, расхождения с sitemap (позже — v1.x).
- JS-рендеринг: headless-браузер (Playwright/Chromium) как переключаемая опция
  сессии; статический fetch — дефолт.
- Соблюдение robots.txt (включая Crawl-delay), опционально отключаемое.

### Не входит в v1 (YAGNI)

Тёмная тема, скриншоты страниц, сравнение краулов, интеграция Google
Analytics / Search Console, аутентификация, многопользовательность,
запланированные (scheduled) краулы, SQLite/дисковое хранение (только JSON-дамп
сессии), рендеринг видео/канвас-контента.

## 2. Архитектура

Подход A: раздельные процессы.

```
seo-crawler/
├── apps/
│   ├── web/        # Vite + Vue 3 + TSX (SPA)
│   └── server/     # Fastify + краул-движок
├── packages/
│   └── shared/     # общие типы: события WS, модель PageResult, типы отчётов
└── package.json    # npm workspaces
```

В dev: Vite-сервер фронтенда с прокси `/api` и `/ws` на бэкенд-порт.
В prod: сборка фронта, Fastify раздаёт статику и API (деплой обсуждается
отдельно, на реализацию v1 не влияет).

## 3. Бэкенд (apps/server)

Стек: Fastify, TypeScript, WebSocket (ws).

### Краул-движок (src/crawler/)

Собственный движок, без краул-фреймворков:

- **Очередь**: приоритетная очередь URL, дедупликация и нормализация
  (удаление `#fragment`, абсолютные URL, склейка дублей).
- **Лимиты**: max URL (по умолчанию 500, настраивается), max глубина,
  таймаут запроса, ограничение домена (внутренние vs внешние ссылки).
- **Конкурентность**: пул воркеров (по умолчанию 5), настройка паузы.
- **robots.txt**: парсится один раз на хост, кэшируется, учитывается Crawl-delay.
- **Режимы** — стратегии первичного наполнения очереди: Spider / List /
  Sitemap (fast-xml-parser; sitemap ищется через robots.txt и стандартные пути).
- **JS-рендеринг**: Playwright, один экземпляр браузера, контекст на страницу.
  Включается флагом сессии; для `text/html` страница рендерится в Chromium
  (ожидание `networkidle`), иначе — обычный HTTP-запрос.
- **HTTP**: undici; **HTML-парсинг**: cheerio.

### Модель данных

`PageResult`: url, статус + заголовки ответа, title/description/meta-robots,
h1–h6, картинки (url, alt-признак), внутренние/внешние ссылки, canonical,
Schema.org JSON-LD, размер/время ответа, флаг рендеринга.

### API

- `POST /api/crawl` — старт сессии (URL, режим, опции).
- `POST /api/crawl/:id/stop` — остановка.
- `GET /api/crawl/:id/pages` — постраничная выдача результатов (пагинация,
  фильтры вкладок/отчётов).
- `GET /api/crawl/:id/issues` — агрегированные отчёты о проблемах.
- `GET /api/crawl/:id/export` — экспорт CSV.
- WS `/ws/crawl/:id` — поток событий: прогресс (просканировано / в очереди /
  ошибки), сводки, готовность страницы, финал. Полные данные страниц через WS
  не передаются.

### Хранение и лимиты

Результаты в памяти (Map по URL), лимит ~50k страниц на сессию, JSON-дамп
сессии по завершении. Глобальный лимит параллельных сессий (3); превышение —
отказ с локализуемым сообщением.

## 4. Фронтенд (apps/web)

Стек: Vite, Vue 3, TSX (все компоненты функциональные: TSX + defineComponent),
Pinia, vue-i18n, vue-router. Без тяжёлых UI-китов — собственная таблица
(сортировка, поиск, пагинация).

### Экраны

1. **Новое сканирование**: URL, режим, опции (лимит URL, глубина, robots.txt,
   JS-рендеринг, конкурентность); для List — textarea и загрузка CSV.
   Валидация с локализованными сообщениями.
2. **Экран краула**:
   - дашборд-полоска: прогресс-бар, счётчики (просканировано / в очереди /
     ошибки), живые сводки (битые ссылки, дубли title, noindex);
   - слева панель категорий и отчётов: Internal, External, Images, Issues;
   - в центре таблица результатов выбранной вкладки; клик по строке —
     боковая панель с деталями страницы;
   - вкладка «Отчёты»: сгруппированные проблемы, клик фильтрует таблицу.
3. **История краулов**: список завершённых сессий, повторное открытие.

### Поток данных

Pinia-стор сессии подписывается на WS и накапливает лёгкие события прогресса;
данные страниц догружаются из REST по мере надобности. При разрыве WS —
авто-reconnect и пересинхронизация из REST.

### i18n и стиль

vue-i18n, `ru.json`/`en.json`, переключатель в хедере, выбор в localStorage.
Светлая тема; нейтральная палитра с одним акцентным цветом; плотные таблицы,
моноширинные URL, статус-бейджи (2xx зелёный, 3xx жёлтый, 4xx/5xx красный).

## 5. Обработка ошибок

- Сетевые ошибки страницы (таймаут, DNS, SSL) → страница попадает в таблицу
  со статусом «Ошибка» и причиной; участвует в отчёте о битых ссылках.
- Ошибки старта сессии (невалидный URL, недоступный хост, пустой List) →
  сообщение на форме, краул не стартует.
- Отвал WS → авто-reconnect, дозапрос прогресса из REST.
- Перегруз: лимиты сессий и страниц, отказ с сообщением.
- Валидация входных данных — на бэкенде; сообщения локализуются.

## 6. Тестирование

vitest на обеих сторонах.

- Краул-движок: юнит-тесты против локального тестового HTTP-сервера
  (мини-сайт с битыми ссылками, дублями, noindex, sitemap) — без сети.
- Парсеры (извлечение из HTML, sitemap, robots.txt): юнит-тесты на фикстурах.
- Фронтенд: стор сессии (WS-события, пагинация), компоненты формы и таблицы.

## 7. Порядок реализации (черновой)

1. Монорепо (npm workspaces) + shared-типы.
2. Краул-движок (+ тесты на локальном тестовом сервере и фикстурах).
3. REST/WS API.
4. Каркас фронтенда (роутинг, i18n, Pinia-стор сессии).
5. Форма нового сканирования.
6. Живой прогресс (WS → дашборд).
7. Таблицы, вкладки, детали страницы.
8. Отчёты о проблемах.
9. Экспорт CSV.
10. Режим JS-рендеринга (Playwright).
